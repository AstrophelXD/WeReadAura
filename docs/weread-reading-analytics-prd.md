# 微信读书个人阅读分析工具需求文档

## 1. 文档信息

- 项目名称：微信读书个人阅读分析工具
- 文档版本：v0.1
- 文档状态：需求草案
- 编写日期：2026-05-16
- 参考来源：[微信读书 Skills 说明页](https://weread.qq.com/r/weread-skills)

## 2. 项目背景

微信读书 Skills 说明页已经暴露出若干围绕个人阅读场景的核心能力，包括：

- 查询书架
- 查询阅读统计
- 查询划线与笔记
- 搜索书籍
- 查询书籍详情与阅读进度
- 获取个性化推荐

本项目希望基于以上能力，搭建一个面向个人用户的阅读分析工具。工具目标不是替代微信读书客户端，而是对用户个人阅读数据做聚合、可视化、趋势分析和复盘，帮助用户更清楚地理解自己的阅读习惯、输入结构和阅读产出。

## 3. 产品目标

### 3.1 总目标

为单个微信读书用户提供一个可持续使用的“个人阅读驾驶舱”，让用户可以查看自己的阅读全貌、阶段趋势、重点摘录与兴趣变化。

### 3.2 关键目标

- 把分散在微信读书内的个人数据汇总成一个统一分析视图
- 让用户能快速回答“我最近读了什么、读得怎么样、留下了什么”
- 支持按时间、书籍、分类、作者等维度进行阅读复盘
- 为后续自动周报、月报、年度阅读总结预留能力

### 3.3 非目标

- 不做公开社交产品
- 不做多人协作书单社区
- 不做电子书阅读器
- 不做写回型能力，初期不修改用户在微信读书中的数据
- 不做大而全知识管理系统，初期仅聚焦阅读分析

## 4. 目标用户

### 4.1 核心用户

- 有稳定阅读习惯的微信读书个人用户
- 希望复盘阅读投入与产出的人
- 习惯做划线、记笔记、收藏书籍的人

### 4.2 用户画像

- 每周至少阅读 3 次
- 对数据可视化和年度总结有兴趣
- 愿意授权读取个人阅读相关信息，但重视隐私与数据可控

## 5. 核心问题

当前微信读书内虽然能查看部分统计和笔记，但仍存在以下问题：

- 阅读数据分散在多个页面，难以形成整体认知
- 时间趋势和阶段变化不够直观
- 划线、笔记、书籍、进度之间缺乏联动分析
- 很难快速生成“最近一周/一月我读了什么、留下了什么”的复盘
- 个性化推荐与用户真实阅读偏好之间缺少可解释的映射

## 6. 产品范围

本期产品范围以个人阅读分析为核心，分为六大模块。

### 6.1 书架总览

功能目标：把用户当前书架变成可筛选、可聚合的阅读资产列表。

功能点：

- 展示书架书籍列表
- 展示基础元数据：书名、作者、封面、分类、状态、最近阅读时间
- 支持按阅读状态筛选：未读、在读、读完
- 支持按最近阅读时间、加入时间、阅读时长排序
- 支持关键词搜索个人书架
- 支持进入单书详情页

分析价值：

- 帮助用户理解自己的待读池、在读池和已完成池结构
- 为后续统计模块提供基础数据源

### 6.2 阅读统计中心

功能目标：把阅读行为沉淀为可复盘的统计指标和趋势图。

功能点：

- 展示累计阅读时长
- 展示累计阅读天数
- 展示已读完书籍数量
- 展示近 7 天、30 天、90 天阅读趋势
- 展示按月份聚合的阅读时长与完成册数
- 展示阅读连续天数与中断情况
- 展示阅读高峰时段分布
- 展示按分类、作者维度的阅读结构占比

建议指标：

- 总阅读时长
- 日均阅读时长
- 月均完成册数
- 近 30 天活跃天数
- 连续阅读天数
- 每本书平均投入时长
- 分类分布占比

分析价值：

- 让用户看到阅读习惯是否稳定
- 识别最近阅读状态变好还是变弱
- 判断阅读是否过度集中在某类主题

### 6.3 划线与笔记中心

功能目标：把“读过什么”升级为“留下了什么”。

功能点：

- 聚合展示所有划线与笔记
- 支持按书籍、作者、时间范围筛选
- 支持按关键字检索划线与笔记
- 支持区分普通划线与带评论笔记
- 展示高频摘录书籍排行
- 展示最近新增划线/笔记时间线
- 支持按单本书汇总该书的摘录密度与笔记数量

分析价值：

- 识别哪些书真正触发了思考和记录
- 为生成个人阅读摘要、主题洞察提供素材
- 让用户快速回顾过去的高价值内容

### 6.4 单书阅读画像

功能目标：围绕单本书形成完整阅读视图。

功能点：

- 展示书籍基础信息
- 展示当前阅读进度
- 展示开始阅读时间、最近阅读时间、完成时间
- 展示该书阅读总时长
- 展示该书划线数量、笔记数量
- 展示该书阅读轨迹：何时开始、何时推进、何时完成
- 展示该书关键摘录列表

分析价值：

- 让用户判断一本书是否读透
- 让用户识别“读完但无产出”和“投入高且收获大”的差异

### 6.5 搜索与发现

功能目标：在个人数据和外部书籍之间建立连接。

功能点：

- 支持搜索微信读书书籍
- 从搜索结果中查看书籍基础信息
- 判断该书是否已在个人书架中
- 如果已在书架，展示个人阅读状态与进度
- 如果未在书架，可标记为潜在待读对象

分析价值：

- 让“想读什么”和“已经读了什么”形成闭环
- 为推荐模块提供用户兴趣反馈

### 6.6 个性化推荐与洞察

功能目标：基于用户已有阅读行为给出可解释推荐。

功能点：

- 展示来自微信读书能力侧的个性化推荐结果
- 给出推荐理由说明，例如题材相近、作者相关、近期兴趣相关
- 支持对推荐结果做“感兴趣/暂不感兴趣”反馈
- 根据书架、统计、笔记行为生成个人洞察文案
- 生成周度/月度阅读摘要

示例洞察：

- 你最近 30 天的阅读主要集中在历史与社会学
- 你在晚间 21:00-23:00 阅读最活跃
- 你最近完成了 3 本书，但笔记主要集中在 1 本书上
- 你对长篇非虚构作品投入更稳定

分析价值：

- 从“看数据”升级为“理解自己”
- 提升工具长期使用价值

## 7. 用户流程

### 7.1 首次使用

1. 用户进入工具首页
2. 用户完成微信读书相关授权或数据连接
3. 系统拉取基础数据并完成首次分析
4. 用户看到个人阅读总览仪表盘

### 7.2 日常复盘

1. 用户进入首页查看最近阅读趋势
2. 用户点击本月完成书籍或阅读时长卡片
3. 用户进入统计中心查看趋势明细
4. 用户再进入笔记中心回顾最近高价值摘录

### 7.3 单书复盘

1. 用户从书架进入某一本书
2. 查看该书进度、投入时长、划线数量和重点笔记
3. 判断是否需要重读、补读或整理输出

## 8. 页面结构建议

建议首版采用以下信息架构：

- 首页仪表盘
- 书架页
- 阅读统计页
- 笔记与划线页
- 单书详情页
- 搜索页
- 推荐与洞察页
- 设置页

## 8.1 视觉与交互风格

前端视觉统一采用 plain neo-brutalism 风格，整体参考 Gumroad 当前首页的核心观感，但需要贴合“个人阅读分析工具”的产品属性。

风格关键词：

- 朴素
- 直接
- 功能优先
- 大标题
- 粗黑边框
- 硬阴影
- 高对比
- 少渐变
- 少装饰

具体要求：

- 页面背景以纸张感浅底色为主
- 卡片、按钮、输入框、图表容器均采用明显黑色边框
- 阴影采用无 blur 的 offset shadow，而非柔和 SaaS 阴影
- 首页和核心页面要有非常明确的分区边界
- 强调色仅用于 CTA、重点指标、推荐和少量高亮卡片
- 避免 glassmorphism、柔和渐变、过度圆润和装饰优先设计

设计落地规范详见 [docs/frontend-visual-style-guide.md](D:\WeReadAura\docs\frontend-visual-style-guide.md)。

## 8.2 首页仪表盘结构建议

首页建议不是企业宣传 landing page，而是“打开就能开始复盘”的个人阅读驾驶舱。

推荐结构：

- 顶部导航
- 大标题 hero 区
- 核心指标区
- 最近阅读趋势区
- 在读 / 已读书籍区
- 最近划线与笔记区
- 推荐与洞察区
- CTA 区

推荐 hero 文案方向：

- 看清你的阅读全貌
- 把读过的书，变成看得见的轨迹
- 从书架到笔记，重新理解你的阅读习惯

## 9. 数据模型建议

首版至少需要抽象以下核心实体：

- `UserProfile`
- `Book`
- `BookshelfItem`
- `ReadingSession`
- `ReadingStatsSnapshot`
- `Highlight`
- `Note`
- `BookProgress`
- `RecommendationItem`
- `InsightReport`

关键关系：

- 一个用户拥有多个书架条目
- 一个书架条目关联一本书
- 一本书对应多个阅读记录、多个划线与多个笔记
- 统计页数据可以由阅读记录和聚合快照共同支撑

## 10. 非功能需求

### 10.1 隐私与安全

- 默认仅面向个人使用
- 仅请求完成分析所必须的数据权限
- 默认不对外公开任何阅读记录、划线、笔记
- 敏感信息不写入前端明文配置
- 提供本地删除缓存与断开连接能力

### 10.2 性能

- 首页首屏应优先返回核心指标
- 列表页支持分页或懒加载
- 大量划线与笔记需要支持增量加载
- 聚合统计需要缓存，避免每次全量重算

### 10.3 可维护性

- API 接入层与业务分析层解耦
- 分析指标口径集中管理
- 关键指标需要可测试、可复算

### 10.4 可扩展性

- 后续可扩展周报/月报/年度报告
- 后续可接入导出 Markdown、PDF、图片海报
- 后续可扩展多终端使用场景

### 10.5 设计一致性

- 前端必须复用统一的 design token 和基础组件
- 同一交互对象在不同页面中应保持相同视觉语言
- 不允许首页、列表页、图表页各自演化成不同设计体系
- 所有新增页面都应先对照视觉规范自检

## 11. 版本规划

### 11.1 MVP

MVP 只解决“看清个人阅读全貌”：

- 书架列表
- 基础阅读统计
- 划线与笔记聚合
- 单书详情与进度
- 基础推荐展示

### 11.2 v1.0

在 MVP 基础上增强分析与复盘：

- 趋势图表完善
- 多维筛选
- 阅读洞察文案
- 周报/月报

### 11.3 v2.0

进一步增强智能化与输出能力：

- 年度阅读报告
- 主题聚类分析
- 笔记摘要与知识卡片
- 导出分享能力

## 12. 风险与注意事项

- 需严格以微信读书 Skills 可提供的实际字段为准，不提前假设不可用数据
- 不同统计指标可能存在平台口径差异，需要在实现阶段统一定义
- 个性化推荐解释能力可能受上游返回字段限制
- 划线与笔记内容涉及个人隐私，默认不做外部分享

## 13. 验收标准

需求文档阶段的验收标准：

- 功能范围明确，能够拆解为开发任务
- 页面结构和数据模型足够支撑首版实施
- 明确了 MVP 与后续版本边界
- 明确了隐私、安全和可维护性要求

后续开发阶段的验收标准将在技术方案与迭代任务文档中继续细化。
