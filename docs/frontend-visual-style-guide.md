# WeReadAura 前端视觉风格规范

## 1. 设计目标

本项目前端统一采用接近 Gumroad 首页核心观感的 plain neo-brutalism 风格，关键词如下：

- 朴素
- 直接
- 功能优先
- 像印刷品
- 大标题
- 粗边框
- 硬阴影
- 高对比
- 少装饰

界面应给人“这是一个认真做阅读分析的工具”而不是“为了炫技而设计的 landing page”的感觉。

## 2. 风格定位

### 2.1 应该呈现的感觉

- 简单、诚实、醒目、可读
- 有一点玩味，但不幼稚
- 信息结构清晰，用户一眼知道每个区块在做什么
- 带有轻微 zine / print poster 的平面感
- 更像功能型创作者产品，而不是典型 SaaS 仪表盘

### 2.2 必须避免的方向

- glassmorphism
- 柔和 SaaS 渐变
- 模糊背景和大面积 blur
- 奢侈品极简黑白风
- 过度卡通化 brutalism
- 假 3D 立体漂浮效果
- 模板化创业公司首页观感

## 3. 核心视觉语言

### 3.1 结构优先

页面结构必须是第一视觉语言，不依赖“微妙留白”表达层级。

优先使用这些结构：

- 全宽 hero / 页面主标题区
- 带边框的功能区块
- 指标卡片与图表卡片
- 书籍卡片与推荐卡片
- CTA 横幅
- 分类标签网格

每个区块必须一眼可判断用途，例如：

- 这是总览区
- 这是最近阅读趋势
- 这是书架列表
- 这是笔记回顾
- 这是推荐区

### 3.2 边框是主语言

统一使用明显黑色边框表达结构，不用轻灰细线撑界面。

推荐规则：

- 默认边框：`2px solid var(--ink)`
- 重点卡片/按钮/导航/弹层：`3px solid var(--ink)`

应加边框的对象：

- 顶部导航
- 一级卡片
- 按钮
- 输入框
- 图片/封面容器
- 图表容器
- 标签
- 模态框
- 下拉面板

### 3.3 阴影必须是硬阴影

统一使用无模糊、带位移的硬阴影。

推荐规则：

- 默认阴影：`4px 4px 0 var(--ink)`
- 大元素阴影：`6px 6px 0 var(--ink)` 或 `8px 8px 0 var(--ink)`

交互规则：

- hover：轻微位移，阴影缩短
- active：进一步下压，阴影消失

禁止使用：

- 大面积柔和投影
- 毛玻璃模糊
- 远距离发光
- 过度分层的 3D 卡片

## 4. 色彩系统

### 4.1 基础配色

页面应以纸张感底色和黑字为主。

推荐色值：

```css
:root {
  --ink: #0a0a0a;
  --paper: #f7f0df;
  --white: #ffffff;

  --yellow: #ffdd33;
  --pink: #ff7ab6;
  --green: #6ee7a8;
  --blue: #7cc7ff;
  --purple: #b79cff;
  --orange: #ff9f43;

  --muted: #e8dcc4;
  --muted-2: #d9cfb8;
}
```

### 4.2 使用规则

- 页面底色优先使用 `--paper`
- 文本默认使用 `--ink`
- 卡片默认使用 `--white` 或 `--paper`
- 强调色仅用于 CTA、badge、重点指标、少量高亮卡片
- 一个页面的主强调色控制在 1 到 2 个，避免满屏跳色
- 默认不使用渐变

### 4.3 与阅读分析场景的结合

建议色彩语义尽量稳定：

- `yellow`：主 CTA、关键增长指标
- `green`：积极状态，如连续阅读、完成进度、活跃天数
- `blue`：信息性模块，如筛选、辅助说明、搜索
- `pink`：推荐、洞察、特别卡片
- `orange`：提醒、中断、待处理项目

## 5. 排版规范

### 5.1 字体方向

建议使用：

- `"Space Grotesk", Inter, system-ui, sans-serif`
- 或 `Inter, ui-sans-serif, system-ui, sans-serif`

如果正文中文显示效果需要优化，可在中文环境下搭配更稳的中文 sans-serif，但整体仍以粗体无衬线风格为主。

### 5.2 字级建议

- Hero H1：`clamp(3rem, 9vw, 8rem)`
- 页面主标题：`clamp(2.5rem, 7vw, 5.5rem)`
- Section H2：`clamp(2rem, 5vw, 4rem)`
- 卡片标题：`1.25rem` 到 `2rem`
- 正文：`1rem` 到 `1.125rem`
- 按钮：`0.95rem` 到 `1rem`

### 5.3 字体风格

- 标题加粗，尽量紧凑
- 标题可用轻微负字距
- 正文保持清晰，不追求花哨排版
- 大段说明文字尽量拆短，适合快速扫读

推荐规则：

```css
letter-spacing: -0.04em;
line-height: 0.95;
```

正文规则：

```css
line-height: 1.5;
```

## 6. 组件级规范

### 6.1 Button

按钮应像实体按钮，明显可点击。

要求：

- 黑色粗边框
- 高对比背景
- 硬阴影
- hover 和 active 有物理压下感
- 主按钮与次按钮层级明显

### 6.2 Card

卡片是本项目主要信息承载单元。

要求：

- 默认白底或纸底
- 黑色边框
- 统一硬阴影
- 内边距稳定
- 不依赖渐变、发光和复杂纹理制造层级

### 6.3 Input / Search

输入框尤其重要，因为书架搜索、笔记搜索是高频操作。

要求：

- 明显边框
- 清晰 placeholder
- focus 态明显
- 不用低对比浅灰边

### 6.4 Badge / Tag

用于书籍分类、阅读状态、推荐理由等。

要求：

- 小尺寸但边界清晰
- 支持少量强调色
- 不依赖颜色单独表达状态，必要时加文字

### 6.5 Chart Card

图表容器必须沿用同一套 neo-brutalism 语言。

要求：

- 图表区域置于边框卡片中
- 图表上方有明确标题与指标摘要
- 视觉风格不应和页面割裂成另一套 SaaS 图表皮肤
- 所有图表都要有文字指标兜底

## 7. 页面模式建议

### 7.1 首页 / 总览页

首页不做传统企业介绍页，而是做“个人阅读驾驶舱首页”。

推荐结构：

- 顶部导航
- 大标题总览 hero
- 核心指标区
- 最近阅读趋势区
- 最近完成书籍 / 在读书籍区
- 划线与笔记回顾区
- 个性化推荐区
- 行动 CTA 区

Hero 文案风格应直接，例如：

- 看清你的阅读全貌
- 把读过的书，变成看得见的轨迹
- 从书架到笔记，重新理解你的阅读习惯

### 7.2 书架页

建议采用“列表 + 卡片”混合风格：

- 顶部有明显搜索和筛选区
- 书籍封面卡片边框统一
- 阅读状态标签醒目
- 排序与筛选控件要有实体感

### 7.3 阅读统计页

建议采用：

- 大号总指标
- 2 到 3 列图表卡片
- 按时间维度分组
- 结论型小文案辅助理解图表

### 7.4 划线与笔记页

建议更强调“内容可读性”：

- 摘录卡片有明确层次
- 书名、时间、标签分区清晰
- 不要让视觉装饰压过文本内容

### 7.5 推荐页

可稍微更活泼，但仍保持节制：

- 推荐卡可用少量强调色
- 推荐理由必须清楚可扫读
- 强 CTA 如“加入待读”要非常明显

## 8. 响应式要求

桌面端：

- 大标题
- 2 到 3 列布局
- 导航链接完整显示

平板端：

- 保持 2 列为主
- 标题适度缩小

移动端：

- 单列布局
- 按钮尽量全宽
- 缩小阴影位移，避免拥挤
- 避免大标题造成横向溢出

## 9. 交互要求

- 使用短促、物理感明确的过渡
- 优先使用 `transform` 实现 hover / active
- 避免所有元素同时动效
- 默认不使用视差和复杂滚动动画
- 支持 `prefers-reduced-motion`

## 10. 可访问性要求

必须满足：

- 明显 focus 态
- 足够对比度
- 语义化 HTML
- 有意义图片提供 alt
- 不依赖颜色单独表达状态
- 键盘可操作

## 11. 实现建议

### 11.1 先定义 token，再写页面

后续实现必须优先建立 design token 层，包括：

- 颜色
- 边框
- 阴影
- 圆角
- 容器宽度
- 字号体系

### 11.2 组件库建议

建议首批抽象以下基础组件，避免每个页面随机发挥：

- `Button`
- `Card`
- `Input`
- `Badge`
- `Section`
- `MetricCard`
- `BookCard`
- `RecommendationCard`
- `ChartCard`

### 11.3 如果使用 Tailwind

- 统一扩展 theme token
- 不要依赖随机 one-off class 拼出视觉风格
- 优先沉淀可复用组件样式

## 12. 落地检查清单

在任何页面实现完成前，至少自检以下项目：

- 页面是否使用 paper-like 背景
- 主要 UI 元素是否都有黑色边框
- 阴影是否为硬阴影且无 blur
- 标题是否足够大、够直接、够易读
- 按钮是否有清晰的 hover / active 状态
- 强调色是否克制使用
- 页面是否支持移动端
- focus 样式是否可见
- 是否误用了 glassmorphism 或柔和 SaaS 渐变
- 是否出现装饰大于信息的情况
